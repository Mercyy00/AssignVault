## Goal
Make /download work end to end: pick the best approved template for the chosen assignment, fill every placeholder with the downloader's details, and return a .docx that looks like the original assignment.

## Tasks

### 1. Template info endpoint `GET /api/template-info?subject=&assignment=`
Returns, for the best approved template: `{ available, requiresFolder, blockCount, warnings: [...] }`. The /download form calls it after the assignment is chosen and shows the **Terminal folder name** input only when `requiresFolder` is true. If nothing is available, show "No file for this assignment yet. Be the first to upload it!" with a link to /upload.

### 2. API route `POST /api/generate`
Validate with zod on the server: subject slug, assignment number, batch id, first name, middle / father's name, surname, roll number, custom date (optional ISO), folder name (only when required). Reuse `/lib/validation.ts`.

### 3. Template selection (`/lib/templates/select.ts`)
Among templates with status `approved` for the assignment choose by: (1) lowest `report_count`, (2) no severe warnings, (3) most recent `approved_at`.

### 4. Filling engine (`/lib/docx/fill.ts`)
Reuse the run model from Step 5. Every placeholder sits in a single run.
- **NAME**: build the string from the `order` roles using the downloader's F, M, S values (for example `order=S-F-M` gives "Sharma Rahul Kumar"). Apply `case` (asis, upper, lower, title). Apply `transform=reverse` after casing (for `Rahul`, `luhaR`).
- **ROLL** and **BATCH**: insert as-is (batch = the batch name).
- **DATE**: format using the placeholder's `fmt`. Date source in this step: the custom date only (Step 8 adds automatic batch dates). If none is provided, return a clear error asking for a date.
- **FOLDER**: sanitize (no `\ / : * ? " < > |`, max 32 chars) and apply `case`.
- **pad=n**: after the inserted value add `max(3, n - value.length)` spaces so a following `Date:` keeps roughly the same position.
- Escape XML special characters in all values. Single pass only; inserted values are never re-scanned (a name containing `{{` must stay literal).
- Leave `<w:drawing>`, footers with page-number fields, and every non-placeholder part untouched.
- After filling, verify no `{{` remains anywhere; if it does, fail safely and log to `audit_log`.

### 5. Response
- Stream the file with `Content-Disposition: attachment; filename="{Subject}_A{number}_{Roll}.docx"` (sanitized).
- Insert a `downloads_log` row (template id, batch, roll, ip hash).
- Rate limit: 20 generates per IP hash per hour.

### 6. Optional flag
Env flag `REFERENCE_WATERMARK` (default `false`). When `true`, append one footer line: "Reference copy generated by AssignVault". One-line change so I can decide later.

### 7. UI on /download
- Live "What will change in your file" card using the entered values (name shown in college order).
- After success show "Report a problem with this file", which calls `POST /api/report` and increments `templates.report_count`; at 3 reports set `needs_review = true`.
- Friendly errors for each server failure case.

### 8. Tests (vitest), using the fixtures
- Generate from templates made out of BOTH fixtures with a different person (First=Asha, Middle=Ramesh, Surname=Patel, Roll=57, Batch=P2, Date=2026-10-01). Assert: all header blocks show the new name, roll and date; `Enter a string:Asha` and `Reversed string: ahsA` appear in the Python output; no trace of the old details; nothing outside placeholders changed (compare the XML with placeholders removed).
- Padding: in the React output the `Date:` label is still on the same line as `Name:`.
- No middle name given: skip the middle role and drop the extra space cleanly.
- XML special characters in the folder name; name containing `{{`; each supported date format; missing date; leftover `{{` triggers a safe failure; output re-opens with JSZip and is well-formed.
